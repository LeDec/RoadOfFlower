# 定制 Agent 与 Skill

## 1. 先定制约束，再定制风格

优先明确允许访问的目录、命令、网络域名、账户、预算、最长步骤数和必须人工确认的动作。语气和角色描述放在这些约束之后。

## 2. Skill 的最小结构

- 名称与触发条件。
- 输入与前置条件。
- 逐步操作流程。
- 输出格式。
- 验证命令或验收标准。
- 失败处理与回滚。
- 权限、隐私和高风险边界。

## 3. 从现有 Skill 派生

不要直接修改上游副本而失去来源。记录原始 URL、固定版本、你的差异和兼容平台。每次上游更新都重新运行测试，而不是盲目覆盖。

## 4. 让定制可测试

为触发条件、正常路径、空输入、错误工具输出、权限拒绝和高风险确认分别准备样例。Skill 的价值不是“写得像专家”，而是行为稳定且可以审计。

## 5. 版本化

把 Skill 当代码管理：语义化版本、变更日志、评审、自动测试和回滚标签。涉及权限扩大的改动必须单独标注。
