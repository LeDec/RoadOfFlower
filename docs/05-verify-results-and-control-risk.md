# 结果验证与风险控制

## 1. 证据优先

验证必须对应可观察事实：文件哈希、测试退出码、数据库行数、API 响应、截图、引用原文位置或独立评审。自然语言自述不能替代证据。

## 2. 三层验证

1. **结构验证**：输出存在、格式正确、字段齐全。
2. **语义验证**：结果回答了真实问题，没有遗漏关键约束。
3. **影响验证**：系统状态、账户、费用和用户体验符合预期。

## 3. 风险分级

- 低：只读、可轻易重跑。
- 中：受控目录写入、可回滚配置。
- 高：外部发送、生产修改、敏感数据。
- 关键：支付、权限授予、批量删除、法律或医疗决策。

高和关键风险必须使用最小权限、审计日志、明确批准人和回滚方案。关键风险不得无人值守执行。

## 4. 停止条件

当来源冲突、验证失败、预算超限、权限不明、工具输出异常或目标发生变化时，Agent 应停止并报告，而不是自行扩大范围。

## 5. 收录边界

RoadOfFlower 只验证索引数据的结构和来源链接格式，不替外部 Skill 做代码审计、恶意行为检测或平台兼容保证。
